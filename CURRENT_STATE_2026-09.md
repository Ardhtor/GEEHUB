# GEEHUB — Current State / September 2026

This is a compact project-state record derived from the latest working conversations. It exists so the repository can retain the direction that would otherwise remain only in chat.

## Current center of gravity

The project is increasingly about **vision**: compiling many nodes of work into something visible, navigable, and alive rather than maintaining a collection of disconnected notes or prototypes.

GEEHUB should therefore function as both an index and a memory-world. The important unit is not only the repository or file, but the relationship between an idea, its source material, its experiments, its visual form, and the next thing it enables.

## Current architecture principle

The durable sequence is:

**mechanism → interface → transformation rule → continuity principle → setting → mythology**

This is a planning grammar, not a requirement that every project literally contain all six layers. It is useful when deciding whether an idea belongs in code, an interface, a world, a canon document, or a separate repository.

Canon and experiments must remain distinguishable. A speculative branch can be developed aggressively without silently becoming established canon.

## Living corpus

The desired corpus is persistent and cross-modal: conversation, local files, browsing discoveries, source material, code, visual experiments, and project history should be able to contribute to the same evolving map.

The corpus should preserve raw passages and source lineage where useful, while extracting durable motifs, coined terms, relationships, unresolved questions, and implementation consequences. Transformation should add structure without destroying the underlying material.

The surface should remain quiet and usable. A visible graph, atlas, browser, map, or other spatial interface is more valuable than a generic feed or dashboard. Complexity can exist underneath the interface without requiring constant interaction.

## New or newly emphasized territories

### Veyrthalis / Veyrthralis

A major fictional world centered on the Foggy Dark Expanse, Florentine/Victorian architectural roots, the Digitorium, Procession, Binding, Temple of Moon, Box/Luke's Box, and related mythic spaces. Its useful structural progression is point → line → plane → space, with maps and ledgers preserving hierarchy and continuity.

### Vision / Living Workspace

The emerging umbrella idea for compiling the project's nodes into a visible environment. This should eventually connect project registry, research, lore, visual work, experiments, and continuity records rather than presenting them as unrelated sections.

### Growth / mass1v1ng framework

The growth-coach work is treated as an imaginative transformation system rather than literal physical coaching. Its useful design vocabulary is progressive scale, accumulation, thresholds, altered baselines, presence, and mutation, with the framework remaining explicitly fictional when used for creative work.

### Visual transformation

Recent image work reinforces a broader requirement for the system: visual artifacts are not secondary illustrations. They can be primary project nodes, with transformations, aesthetic decisions, and relationships preserved as part of the project's history.

## Build implications

1. Keep GEEHUB machine-readable enough that another interface can consume its registry without rewriting the corpus.
2. Preserve links between projects, experiments, visual artifacts, research trails, and source conversations.
3. Prefer durable metadata and provenance over opaque summaries.
4. Add a new repository only when independence materially improves the work.
5. Let mature concepts become their own repositories while keeping a backlink into the constellation.
6. Treat recent conversation as project input, but do not manufacture edits merely because new conversation exists.
7. Favor interfaces that make relationships visible: atlas, map, graph, timeline, spatial browser, or other direct-manipulation surfaces.
8. Keep restricted or copyrighted source material as references and metadata unless storage and redistribution are clearly permitted.

## Near-term opportunity

The most important missing layer is a real **GEEHUB constellation interface** above the current BodyLounger application. The existing archive is a useful first application, but it should not remain the accidental identity of the umbrella repository. The next substantial interface should make the project constellation itself visible while allowing the BodyLounger archive to remain a dedicated territory within it.
