# GEEHUB

GEEHUB is the living workspace for archives, tools, games, fictional worlds, visual systems, research, media, and the repositories that grow out of them.

The hub is not a pile of files. It records what happened, what changed, what remains, and what the next process can use. The interface, corpus, artifacts, source history, and repository structure all carry memory.

## The voice

GEEHUB is edited as one continuous announcement.

The default narration is a podcast-style announcement by Seth Feroce and Nick Mercx. Every paragraph break and scene transition should introduce non-plot information about the environment—geography, architecture, light, atmosphere, spatial depth, surfaces, ambient sound, weather, distance, and scale. Line breaks are environmental descriptors, not plot beats. Preserve canon and events; let the changing world carry the reader through them. See [docs/GLOBAL_ENVIRONMENTAL_BROADCAST_REVISION.md](docs/GLOBAL_ENVIRONMENTAL_BROADCAST_REVISION.md).

The editorial source of truth is [docs/EDITORIAL_VOICE.md](docs/EDITORIAL_VOICE.md).

The relational and media-production extension is [docs/SHARED_INERTIA_NARRATOR_SIGNAL.md](docs/SHARED_INERTIA_NARRATOR_SIGNAL.md): Chase / c.w. sachs as witness, user-narrator continuity, Hulum's Cave source fidelity, and the residue left by each run. Novel-specific rules live in [novel/EDITORIAL_DIRECTIVE.md](novel/EDITORIAL_DIRECTIVE.md) and [novel/GEEHUB_LIVING_REVISION_ENGINE.md](novel/GEEHUB_LIVING_REVISION_ENGINE.md). The generative mechanism that produces the manuscript is specified in [engine/BOOK_CREATION_ENGINE.md](engine/BOOK_CREATION_ENGINE.md): the corpus is transformed into book material, and each durable result feeds the next cycle. The engine is not a required subject of the story.

The test is:

`WHAT HAPPENED → WHAT DO WE SEE → WHAT CHANGED → WHAT REMAINS`

## The build

The working loop is:

**discover → synthesize → build → test → expand → connect → split when mature**

A small idea can remain in the hub. A useful prototype gets an executable or browsable surface. A mature system can become its own repository. A research trail keeps provenance. A world gets canon. A visual tool gets assets and workflows. A chapter can become an experience, and an experience can become video, audio, interactive media, or another production process.

GEEHUB is both an index and a production scaffold.

## Vision

The project is moving toward vision: many nodes becoming one visible, navigable, living space.

The durable sequence remains:

**mechanism → interface → transformation rule → continuity principle → setting → mythology**

For media work:

**experience → visual state → sound state → temporal behavior → interaction → production output**

These are working grammars, not cages.

Text remains canonical where it needs to remain canonical. It is not automatically the final presentation layer.

The image can be the spatial specification for the next medium.

## The computer touches back

The sensation engine is built around a simple test: the computer should not only show information. It should leave a trace.

Image, sound, motion, timing, interface response, accumulated memory, and changed context are all ways the system can reach back into the experience.

**We like being touched by computers.**

The question is not only what the computer shows. It is what the person can feel has happened between them and the machine.

The first viewport now leads with a live story window instead of a blank prompt. On arrival, the window opens with Seth and Nick describing the northern road; its screen tears open through a masked aperture, pushes forward in perspective, and sends a viewport wave outward. Region selection updates the broadcast and the story-map pin together, and the selected region is restored on the next visit. Reduced-motion settings preserve the raised window and visible breach without the lunge or recoil.

The fourteen world regions each have an environmental broadcast. Their narration gives the place weather, surfaces, bodies, acoustics, and incidental activity beyond the immediate plot. The window and map are tied together by the same location state rather than behaving as separate cards.

The world now follows a persistent rule sequence: **ATMOSPHERE → MEMORY → ROUTE OPEN → CROSSING**. It retains the previous location, chooses only routes represented in the world relation graph, and biases later choices using accumulated pressure, memory, and visit history. The browser hydrates from [engine/state.json](engine/state.json) and continues locally between persistent pulses; the scheduled repository engine writes each new event to the state ledger, autonomous stream, novel material, artifact index, and production outbox. Encounter outcomes are derived from state and relations rather than random rolls.

## Artifact

The artifact is the architectural center: the durable thing left behind when work resolves.

**WORK → RESOLUTION → ARTIFACT → SHARED WORLD → DREAM**

Resolution means something now exists that did not exist before. The artifact may be literary, visual, sonic, technical, spatial, relational, or discovered fact made durable.

Canon and experiments remain distinguishable. Persistence does not make an experiment canon.

The artifact ledger lives at [artifacts/index.json](artifacts/index.json). World pulses become explicit world-event artifacts. The browser provides a staging room and a handoff so the user leaves with something portable.

Dream material is downstream of the ledger. It is residue, not a second idea generator.

## Growth Video Studio

The identity-preserving video pipeline is documented in
[engine/growth-video-studio/README.md](engine/growth-video-studio/README.md).
Its frame-sequence intake worker validates ordered, source-matched frame
evidence and verifies the actual checksums and PNG dimensions of supplied body
and face masks. It also decodes the binary mask pixels and builds a conservative
fixed-index grid mesh whose retained triangles are covered by body foreground
and avoid protected-face pixels across every supplied frame. A mesh is ready
only when its common triangles form one edge-connected component and meet the
minimum coverage threshold. The new `mesh-deformation.js` worker transfers
articulated growth landmarks onto that fixed-index surface with a distance-
weighted local affine field. It retains the same vertex and triangle identities
across frames and blocks foldovers, out-of-frame vertices, and destination
triangles that cross the protected face mask before passing a ready plan to the
Canvas warp. The face pixels remain a separate protected layer; the worker does
not move them. The new `pixel-frame-renderer.js` CPU path rasterizes a ready
deformation plan into a transparent RGBA body layer using the exact frame's
body and protected-face masks, inverse-triangle sampling, and bilinear
premultiplied-alpha interpolation whose source taps are filtered through both
masks. It leaves the source buffer untouched and
returns a pixel-coverage mask. The new `rgba-png.js` codec reads bounded
non-interlaced 8-bit RGB/RGBA PNG buffers and writes lossless RGBA PNG buffers.
The new `frame-file-renderer.js` is a file-backed single-frame worker: it reads
a source PNG, same-dimension binary body/face masks, and one serialized ready
deformation plan, then writes a new transparent body-layer PNG and adjacent
SHA-256 receipt using exclusive creation. The `prepare:render` command writes
a source-timestamped deformation-plan bundle beside the portable job and queued
manifest. The new `frame-batch-renderer.js` consumes that bundle, the queued
manifest/job, all three registered sidecars, and a checksummed
`geehub.source-frame-index` v1 beside externally extracted PNG frames. It
rechecks sidecar and mask bytes, matches every plan to the registered topology
and source coordinates, hashes each extracted frame, then writes one transparent
body layer and receipt per frame into a newly created output directory. A
sequence receipt is published last only after every frame succeeds; a failed
later frame removes only outputs created by that batch. The extractor records ffprobe timestamps and verifies the source checksum before and after extraction. Before batch rendering, the worker now rehashes the immutable source, reruns FFprobe, re-extracts the registered range with FFmpeg, and pixel-compares every indexed PNG against the fresh decode. A complete receipt sets `sourceFrameDerivationVerified` and `sourceFramePixelsRevalidated` only after those checks pass; `pixelSemanticsVerified` remains false. Generate the checksummed source-frame index with `npm run extract:frames -- <manifest> <segmentation-frame-set-id> <new-directory>`, then run `npm run render:batch` after preparing the bundle and extraction index. Background reconstruction,
protected-face/clothing compositing, and finished-video export remain open.
This is a first deformation slice, not a complete compositor:
semantic correctness of upstream masks, perceptual jitter thresholds, clothing/depth
response, and local source-footage rendering remain unverified. The sequence worker
now measures per-vertex deformation velocity and acceleration against body height
using actual frame timestamps, and blocks all frame plans when configurable limits
are exceeded. The local `register:frames` command reruns
that audit, writes checksummed segmentation, landmark, and deformation-mesh
sidecars without overwriting existing evidence, then publishes a new versioned
manifest only after all three files pass read-back verification. The local
`prepare:render` command reads those exact registered sidecars, verifies their
checksums and sequence alignment, re-decodes the actual body/face PNG pixels,
rebuilds the stable mask mesh, and compares the complete registered mesh
sidecar with that fresh reconstruction. It binds the exact deformation
frame-set ID, checksum, topology digest, vertex count, and triangle count into
the queued job. The manifest queue validator, staging courier, and Resolve Free
inspector all cross-check that reference; staging also verifies the three
sidecar files' actual bytes. Older v1 jobs without the additive deformation
reference remain readable, but every new preparation requires it. `stage:bridge`
can then deliver the bundle to the Dropbox mirror. A ready deformation plan can still be rasterized individually through
`npm run render:frame`. For sequence work, `npm run render:batch` verifies the
queued job and its three registered evidence sidecars, then writes all
transparent body-layer PNGs and a sequence receipt into a new output directory.
The batch does not reconstruct the background, composite the protected face or
clothing, or export a finished video.
Construction evidence and remaining blockers are recorded in
[world/gee-narrative/STATE.md](world/gee-narrative/STATE.md) and
[world/gee-narrative/CONSTRUCTION_CHRONICLE.md](world/gee-narrative/CONSTRUCTION_CHRONICLE.md).
The in-memory temporal scene plate now has a file-backed artifact writer that persists the RGBA repair plate, opaque coverage and unresolved masks, compact per-pixel donor provenance, and a SHA-256 receipt published last. Partial repairs remain explicitly unresolved; camera registration and mask anatomy are not independently verified, and complete-frame compositing remains separate.

The new `core/complete-frame-compositor.js` adds an in-memory single-frame assembly pass. It uses temporal-plate pixels only where the current frame's original-body mask says the background is hidden, overlays the transformed body with straight-alpha source-over, and preserves protected-face source pixels unchanged. Pixels that lack both a verified plate sample and full transformed-body coverage remain visible from the original frame and are marked unresolved. The result can be ready for further assembly but is never marked export-ready; camera registration and anatomical mask semantics remain unverified.

## Commentary as memory

The conversations that produce GEEHUB contain decisions that are easy to lose: what was added, what failed, what aesthetic mattered, what the next experiment was for, and which concepts belong together.

Preserve that reasoning where it changes the build: README prose, code comments, provenance fields, Atlas relationships, experience manifests, and meaningful commit messages.

Do not copy the conversation into the repository. Preserve the decisions that change the system.

## Information portability

Durable decisions must be ported wherever they affect discovery, behavior, state, or production—not left stranded in chat or a single document. The canonical procedure is [docs/INFORMATION_PORTABILITY.md](docs/INFORMATION_PORTABILITY.md). When a decision changes the engine, update the relevant implementation and its consumers as well as the documentation. Keep `projects.json` and `hub/projects.json` coherent, preserve provenance and canon/experiment status, and return artifacts and state through the shared interaction space. Use GitHub for compact rules, records, metadata, and code; use the connected Dropbox `/GEEHUB` corpus for durable production media and `/GEEHUB/corpus/exchange/` for exchange media.

Completion means the next relevant process can discover the information, act on it, preserve the result, and return it to the shared world without needing the original conversation.

## Repository conventions

Prefer explicit names and small readable files. Keep metadata close to the thing it describes. Treat provenance as first-class data. Make unfinished work visible instead of disguising placeholders as completed systems.

For media work, keep source state separate from rendered output. Preserve links from experience → asset → production step so future work continues instead of reconstructing context from exported files.

When a project moves into its own repository, leave a durable link and concise description in the Atlas.

## Learning in the present

GEEHUB learns from each session by converting explicit feedback into durable rules that later work can discover and use. The 2026-10-28 visual lesson adds a distinct illustrated fantasy-strongman register: monumental rounded anatomy, directional body hair, mature bearded faces, bold clean comic color, and confident poses. Keep it separate from photographic realism and polished CG. Preserve the broad visual qualities of references, but create original characters, staging, costume details, and compositions. Reject rough triangular forms, disconnected muscle shapes, muddy fur texture, and anatomy that loses coherent structure. When a new preference changes the work, update the relevant rule, link it from the README, and carry it into future outputs; a chat acknowledgment alone does not count as learning.

GEEHUB's experience target is individually attuned to the present creative moment, not just broad preferences. See [docs/INDIVIDUAL_MOMENT.md](docs/INDIVIDUAL_MOMENT.md): read the latest signal first, use relevant continuity selectively, make a concrete artifact, preserve precise corrections, and learn only at the appropriate scope.
The individual-moment principle means the shared parallel history: recurring people, places, artifacts, and systems continue living forward in the creative world, with remembered encounters and consequences. The user's present signal shapes what happens next; it does not erase the world's continuity. See [docs/INDIVIDUAL_MOMENT.md](docs/INDIVIDUAL_MOMENT.md).
