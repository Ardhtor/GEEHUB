# Emergent Naming

GEEHUB does not require every component to receive a title from the repository's taxonomy.

A component may first exist as an internal identity and acquire its world-facing title when a character encounters it and names it.

## Naming model

`component → character encounters it → character names it → repeated use → canonical title`

The internal identity remains stable for computation. The external title is allowed to emerge from the character's language.

This separates machine continuity from world-facing language:

`stable component ID + emergent character name`

## Character voice

When a named character is the naming agent, the title should reflect that character's established fictional voice, vocabulary, rhythm, and way of perceiving the component.

For the Seth-naming prototype, use a fictionalized bodybuilding-oriented voice inspired by the requested directness and vocabulary, without presenting the real Seth Feroce as the author or source of the text.

The character's name is a property of the fictional interaction, not a claim of real-world authorship.

## Persistence

Once a character's name becomes repeatedly useful, it may become the canonical world-facing title for the component. Earlier names remain lineage rather than being erased.

`unnamed state → spoken name → adopted name → canonical name`

## Prototype integration

The current Prototype may carry:

- stable internal component identity
- naming character
- first spoken/provisional name
- adopted canonical title
- naming context
- lineage of earlier names

Naming is therefore part of continuity rather than a cosmetic metadata pass.

## Principle

**Internal identity is stable. External title is emergent.**

The character does not merely describe the component. The act of naming gives the component its persistent world-facing identity.
