# CONTINUAL MONITOR

The monitor is part of the corpus process, not an external supervisor.

Its purpose is to let the program repeatedly encounter its own accumulated material and observe what changes.

`PROCESS → MONITOR → RESPONSE → MEMORY → PROCESS`

Each pass may:

- observe the current state
- interpret what changed
- compare the current state with prior states
- remember recurrence and provenance
- anticipate emerging structure
- test an interpretation against the corpus
- detect cognitive drift or contradiction
- preserve what remains continuous
- interrupt or flag unsafe/coercive transformations
- realign cognition with agency, boundaries, continuity, and the actual corpus
- integrate the result back into the next pass

The monitor does not assume that a detected pattern is correct. It records hypotheses, recurrence, uncertainty, and counterevidence.

## IGNITION / DELIMITER

Small recurring formations are first-class observations. A fragment such as `ija` is an ignition exemplar: its significance is determined by recurrence and by the structures that appear around its occurrences.

The parser therefore searches for:

`small recurring unit → interval → recurrence → emergent theme`

Themes are not imposed in advance. A recurring theme can function as a delimiter when its appearances partition the corpus into meaningful intervals.

## RECURSIVE LOOP

`CORPUS → PARSE → RESPONSE → CORPUS`

The program's own responses become corpus material. The monitor observes both source material and prior program responses, preserving the distinction between them.

The visual tree is downstream of this process:

`CORPUS → RECURRENCE → THEMATIC DELIMITERS → INTERVALS → RELATIONS → TREE`

The tree is therefore a visualization of an emergent parse, not a predefined taxonomy.
