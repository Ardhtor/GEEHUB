# EXPERIENCE-FIRST ARCHITECTURE

GEEHUB is moving from a document-first hierarchy toward an experience-first hierarchy.

## Core idea

A story event is not necessarily a chapter-shaped piece of text.

It is a **media event** that can acquire different manifestations.

```
EVENT
  ↓
EXPERIENCE
  ├─ prose
  ├─ visual states
  ├─ voices
  ├─ sound
  ├─ interaction
  ├─ timing
  └─ production scaffolding
       ↓
     VIDEO / AUDIO / WEB / OTHER MEDIA
```

## Stratification

The layers are intentionally different:

`canon/`
What is true in the world.

`experience/`
How that truth is encountered.

`state/`
The discrete visual, sonic, spatial, or interactive states that compose the experience.

`assets/`
Reusable source material.

`production/`
Shot lists, timing, edit logic, voice cues, scene continuity, and other instructions for making a temporal work.

`render/`
Exported media. Rendered outputs are downstream artifacts, not the source of truth.

## Chapter model

A chapter can therefore become:

```
novel/
  CHAPTER_XXX/
    prose.md
    experience/
      manifest.md
      states/
      voices/
      sound/
      interaction/
    production/
      shots.md
      timeline.md
```

The exact directory layout can evolve. The important invariant is that **the experience remains between canon and production**.

## The Convergence

The current Convergence work is the first concrete example:

`The Convergence → Clearing → Voice Geography → Serum Depth → voice / sound / timing → shot sequence → video production`

The existing Adobe images are therefore treated as **state prototypes**. Their value is not only aesthetic. They establish composition, spatial relationships, visual grammar, atmosphere, and possible transitions for a later temporal medium.

## Production rule

Do not force video production prematurely.

First establish what the experience is.

Then determine:

`what changes`
`what remains continuous`
`what the viewer hears`
`what the viewer sees`
`what moves`
`when it moves`
`what the next process needs`

This makes each layer useful even before the final medium exists.

## Direction

The Hub should increasingly answer:

**What could this become next?**

rather than only:

**What file is this?**

That distinction is the reason for the reorientation.
