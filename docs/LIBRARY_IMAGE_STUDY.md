# Library Image Study

Status: visual corpus study, 2026-11-09  
Scope: 234 image files returned by the ChatGPT Library image inventory across three listing pages. This document is a working interpretation of the available visual corpus, not a claim that every file has been exhaustively classified at pixel level. Filenames are retained as inventory identifiers; visual observations are marked separately from title-based grouping.

## 1. The corpus has several distinct layers

The library is not one undifferentiated image set. It contains at least six overlapping bodies of material:

1. GEEHUB and Tractus interface concepts.
2. Character references and recurring physique studies.
3. Growth sequences, phase charts, morph comparisons, and transformation montages.
4. Inhabited settings: gyms, locker rooms, bedrooms, homes, workshops, outdoor places, forests, estates, and cities.
5. Mythic and symbolic imagery: continuity, corruption, cosmic scale, shrines, gods, and enchanted landscapes.
6. Source captures and personal/reference photographs, including files whose names preserve their original platform or capture context.

These layers should remain connected, but they should not be collapsed into one prompt collection. An interface image, a face reference, a transformation phase, and a location photograph serve different production functions.

The important technical distinction is between a *phase label* and a *measured transformation*. A chart may propose a sequence; it does not establish biological, geometric, or temporal measurement unless its axes and source data support that interpretation. Keep stage names, source image, character identity, camera, and any actual measurements together.

A useful transformation record should capture:
- subject / character ID;
- source image and derivative relationship;
- phase label and whether it is proposed or observed;
- camera angle, lens impression, pose, and crop;
- head-to-body relationship;
- shoulder, chest, waist, arm, thigh, calf, and hand/foot proportions;
- clothing and fit changes;
- environmental scale references;
- unresolved continuity differences.

The “oversized vs frozen head” comparison is especially important as a warning: if the body grows while the head remains fixed, the result may become a deliberate stylization, but it should not be mistaken for neutral character continuity. The choice must be explicit.

## 5. Environments as scale instruments

The library includes a wide range of settings. They should be treated as persistent places with their own material and social logic.

**Gym and training spaces**
- industrial gyms, cool-toned gyms, moody gyms, modern gyms, wood-paneled gyms;
- locker rooms and equipment-heavy interiors;
- home gym and bedroom training scenes.

**Domestic and social spaces**
- modern living room, minimal bedroom, bedroom scenes, lounge interiors;
- shared gym portraits and friendly fist-bump scenes;
- kitchen/chef references and food-related scenes.

**Outdoor and transitional spaces**
- beach and lifeguard scenes;
- green terrace and urban stoop;
- modern glass-house entrance;
- workshop and rustic interiors;
- twilight mountain lodge and forest.

These environments do more than provide backgrounds. Doorways, benches, lockers, gym equipment, chairs, ceilings, beds, kitchen counters, and vehicles can all act as scale references. A character's presence should change how the environment is read, while the environment remains materially consistent across shots.

The workshop and wood-paneled references are particularly useful for connecting the visual corpus to GEEHUB's physical-material preference: wood, beams, built interiors, repair spaces, and durable construction. The forest material belongs to the Veyrthalis visual family and should retain its darker, more atmospheric treatment rather than being recolored into the gym palette.

## 8. Source material, captures, and provenance

The inventory also contains source-like filenames and platform captures: numbered camera files, screenshots from Instagram, TikTok, Reddit, Facebook, Tumblr, and other files with hashes or opaque names. These must not be automatically relabeled as generated art or treated as approved production assets.

Keep four statuses distinct:
- **Reference:** consulted for visual understanding.
- **Source:** original file or captured item with known provenance.
- **Derivative:** an edit, crop, generated variation, or composite made from another item.
- **Production-approved:** cleared for a specific use after rights and source restrictions are checked.

A filename is not a rights statement. Preserve any visible NoAI or other use restriction with the source record. Do not use restricted images for generation, training, or derivative production. In particular, the separate GravesBeef archive record for Image (31) retains its “Trial NoAI” label and must remain restricted unless the source owner clarifies otherwise.

## 9. Recommended corpus structure

Organize the image library by function while retaining links between related files:

- `visual/characters/` — identity anchors, face references, body continuity sheets.
- `visual/growth-sequences/` — ordered phases, comparisons, charts, transformation montages.
- `visual/environments/` — gyms, homes, workshops, outdoor spaces, cities, forests.
- `visual/mythology/` — gods, symbolic plates, corruption, continuity, shrines.
- `visual/interfaces/` — observatory, console, archive, map, dashboard concepts.
- `visual/source-captures/` — original photographs, platform screenshots, and unclassified inputs.
- `visual/derivatives/` — crops, edits, composites, and generated versions, each linked to its parent source.

Do not physically move the Library files as part of this classification. This is a logical index proposal; the original Library remains intact.

## 10. Production rules derived from the study

1. Identity before scale. Lock the character's face and recognizable features before changing body dimensions.
2. Scale must be legible. Include stable environmental references where size change matters.
3. Preserve the camera. A change in camera distance or lens impression can masquerade as body growth.
4. Keep stages ordered. Do not blend alternate phases into a false continuous sequence.
5. Separate reference from canon. An image can inspire a character without becoming that character.
6. Give places memory. Reuse the same room, equipment, furniture, landmarks, and lighting logic across scenes.
7. Include ordinary states. Every major character needs non-transformational images and activities.
8. Preserve source restrictions and provenance. NoAI and other limitations travel with the image record.
9. Treat generated interface text as visual placeholder unless transcribed and checked.
10. Build modularly. Extract reusable people, clothing, props, furniture, architectural pieces, lighting setups, and environment components rather than defaulting to one-off posters.

## 11. Tractus interpretation

The image corpus is a record of reciprocal transformation. The user's visual attention changes what GEEHUB emphasizes; the evolving GEEHUB visual language changes how future images are selected, interpreted, and produced. The archive therefore needs both continuity and revision history.

A useful image record is not simply “what is pictured.” It records what the image was used to understand, what it changed in the project, what remains uncertain, and which later images inherit or contradict it.

The file-by-file visual pass is underway in the [Library Image Atlas](LIBRARY_IMAGE_ATLAS.md). It assigns stable image IDs, records Library file IDs, states why each image is relevant, and keeps private or restricted material out of the project corpus. The first five inspected files are indexed; the remaining inventory is still in progress.


## 12. Referencing Library images inside GEEHUB

The user has explicitly authorized GEEHUB to reference relevant Library images when the reasoning for the reference is present. This makes the image corpus an active visual reference system, not merely a background study.

A GEEHUB page, character record, location entry, artifact, or production note may therefore point to a Library image when it materially helps explain a design decision. Each reference should carry a short rationale: what visible feature is being referenced, what project question it helps answer, and whether the image is a direct identity reference, a compositional reference, an environmental reference, or a general stylistic influence.

Use the following compact record:

- **Image:** exact Library filename or stable file reference.
- **Reason:** the visible feature or design problem that makes it relevant.
- **Use:** identity / proportion / pose / clothing / environment / lighting / composition / interface / symbolism.
- **Relationship:** reference only, continuity anchor, comparison, or derivative source.
- **Restriction:** preserve any source label or usage limitation.

Do not make a reference appear stronger than the evidence supports. If the image is only a broad influence, say so. If it establishes a recurring character's appearance, identify the specific visible continuity features. If two images conflict, preserve both and record the discrepancy instead of silently choosing one.

This authorization concerns referencing images in GEEHUB with an accompanying rationale. It does not erase source restrictions or convert a reference into an approved derivative, training source, or redistributed asset. The GravesBeef Image (31) record marked “Trial NoAI” remains restricted. Where the actual Library image cannot be embedded or its stable source link is unavailable, use its exact filename and Library reference rather than inventing a public URL.

The governing rule is simple: every image reference should explain what it contributes to the world.
