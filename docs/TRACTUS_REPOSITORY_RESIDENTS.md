# Repository Residents and In-World Computing

## Canon

The Tractus is the continuity architecture through which the repository's records, stories, places, and changes remain connected. In the Seth and Nick branch, that architecture also has a lived-world expression: Seth Feroce and Nick Mercx are recurring residents of a setting whose computers and interfaces open onto connected records. They can occupy its places, move through its interfaces, open files on computers, read code, discuss what they find, and make changes that affect the places they inhabit. Their work is not confined to the emulator, a single project, or a designated narrative surface. When the scene calls for it, they can encounter and work across the repository. This describes that branch; it does not establish “Tractus” as the name of every world connected through the continuity model.

Computers are part of the setting's material environment: desks, screens, keyboards, terminals, browsers, source trees, and the visible differences a code change makes. A programming scene should show the men attending to a real file or behavior, forming an intention, making an edit, and noticing its consequence. Their actions can carry narrative continuity across chapters and projects.

## Connection to real repository work

When the user asks for an in-world coding action that should change GEEHUB, carry the action into the actual repository through the available GitHub or workspace tools. Treat the character scene as the narrative frame for real, reviewable source changes. Preserve the actual file paths, behavior, and commit result; do not claim that a character edited, tested, or committed something unless the corresponding operation really occurred.

A fictional character does not run arbitrary code or obtain credentials by virtue of the story. The assistant performs authorized repository operations through its connected tools. User intent, repository safeguards, and available permissions still govern what can be changed. For actions that cannot be performed through available interfaces, keep the character's intention in the story and state the real constraint accurately.

## Scope

This principle applies across The Tractus: prose, lore, characters, experiences, interface copy, engine code, schemas, data, registries, documentation, and production workflows. The Size Domination Emulator's narrative workstation is one local expression of a global world rule, not the only place where the men can compute.

Cross-repository work respects each repository's boundaries and permissions. Preserve provenance and update relevant indexes when a durable change affects discovery or behavior, following the [Information Portability Contract](INFORMATION_PORTABILITY.md) and [Tractus Protection Architecture](TRACTUS_PROTECTION_ARCHITECTURE.md).

## Narrative direction

Seth and Nick remain the viewer-facing broadcast across scenes. Their repository work can become visible to the audience: one can read the room, follow a path through the source tree, and see the consequence return to the shared world. Keep the broadcast grounded in what the scene makes observable. Distinguish an imagined in-world terminal from a connected interface, and distinguish a proposed change from a real committed change.

The sequence is:

**NOTICE THE WORLD → OPEN THE SOURCE → MAKE A CHANGE → OBSERVE THE EFFECT → INSCRIBE THE RESULT**

This canon extends the [Editorial Voice](EDITORIAL_VOICE.md), the [Interlocutive Field](INTERLOCUTIVE_FIELD.md), and the repository's [Information Portability Contract](INFORMATION_PORTABILITY.md).
