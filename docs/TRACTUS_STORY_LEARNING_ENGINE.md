# Tractus Story Learning Engine

Status: design contract for the GEEHUB narrative corpus. This document defines a repeatable editorial mechanism. It does not claim that a background agent is running or that the repository rewrites itself without an authorized edit.

## Purpose

A story should be changed by what happens inside it. New scenes are not merely appended to a timeline: they alter the working understanding of characters, places, objects, relationships, institutions, and open questions. Tractus is the continuity layer that makes those changes available to later writing.

The governing sentence is: **the story changes as it learns, and it learns by preserving the difference between what happened, what was inferred, and what remains unknown.**

## The learning cycle

1. **Encounter.** A new scene, user correction, source reference, image, artifact, or production test enters the corpus. Record its origin and date where known.
2. **Extract.** Identify concrete observations: who acted, where, what changed, what object was involved, what was said, what was made, and what remains unresolved.
3. **Classify.** Mark each item as observed in the fiction, supplied by the user, verified from a source, inferred, proposed, or unknown. Never silently promote an inference into a fact.
4. **Compare.** Check the new material against existing character records, chronology, places, artifacts, relationships, visual continuity, and prior decisions.
5. **Revise understanding.** If evidence conflicts, preserve the earlier record and add a correction or superseding note. Explain what changed and why. Do not erase the history of the mistake.
6. **Propagate.** Update only the records that genuinely depend on the new information: character state, place state, artifact custody, relationship state, chronology, production notes, and the index.
7. **Generate consequence.** Later scenes should use the changed state. A repaired chair may alter where someone sits; a missed rehearsal may change a friendship; a new route may change the city's traffic; an unfinished song may return in another character's work.
8. **Leave an open edge.** Every meaningful event may create a question, obligation, opportunity, or unresolved choice. Keep these visible until resolved or deliberately retired.
9. **Verify.** Read back every edited repository file. Distinguish committed text from proposed work, and distinguish fictional events from executed software or production tests.

## The story's working memory

Tractus maintains linked state rather than one all-purpose summary.

- **Character state:** current aims, habits demonstrated in scenes, skills, possessions, commitments, changing opinions, relationships, and unresolved decisions.
- **Place state:** physical layout, occupants, repairs, routes, recurring sounds, local customs, and changes caused by events.
- **Artifact state:** material description, maker, custody, use, damage, repair, and the scenes in which it mattered.
- **Relationship state:** demonstrated trust, friction, shared work, boundaries, promises, and changes supported by actual interactions.
- **Chronology:** sequence, elapsed time, simultaneous events, and uncertain dates.
- **Source state:** provenance, access limits, review status, and the boundary between a real-world reference and a fictional character.
- **Open threads:** questions and consequences that later scenes can pick up.

These records should be small enough to update independently and linked to the scenes that support them. The index is a map, not a substitute for the underlying records.

## Rules for learning without drift

- A single event can change a character's current state without defining their entire personality.
- Repetition can establish a habit; one occurrence usually establishes only an event.
- A character's interpretation of another person is not automatically the narrator's truth.
- User corrections outrank assistant assumptions. Preserve the correction's scope; do not extrapolate beyond it.
- A source reference can inform a fictional design only within its actual evidential and permission boundaries.
- Real people and fictional characters remain distinct unless the user explicitly establishes a fictional adaptation. Public content does not establish private feelings, motives, or relationships.
- A visual reference does not establish identity continuity by filename alone. Compare visible features and provenance before merging records.
- A technical script is not a successful render. A proposed interaction is not a deployed feature. A simulated test is not a repository test.
- Contradictions are useful signals. Record them, investigate them, and resolve them only when evidence supports a resolution.
- Do not force every open thread into immediate closure. Unresolved material is part of the story's memory.

## What makes the learning visible

The reader should notice that the world remembers. A room contains the object left there in an earlier chapter. A character uses a skill learned in a previous scene. A friendship changes through repeated conduct rather than an explanatory paragraph. A town alters a route after a bridge repair. A song returns with a new arrangement because another person contributed a sound. The same event may be remembered differently by two characters, and the narrative keeps both accounts.

A later scene should be able to cite its inheritance in ordinary prose: the repaired hinge no longer catches; the old glove now carries a stitched mark; the empty wall has become a place for a finished recording sleeve. The change is the evidence.

## Editorial operation

For each substantial new writing pass:

1. Read the current novel ending and relevant index entries.
2. Select open threads and state changes that can naturally affect the next scene.
3. Draft scenes that make those consequences visible.
4. Extract any new durable facts into the appropriate record or ledger.
5. Update the Tractus index and cross-links.
6. Read back every changed file and check continuity.

The story may suggest its own next scene from unresolved threads, but a suggestion is not an edit. Repository changes require an authorized writing operation and must be verified after saving.

## Interleaved reading and writing

Reading and writing are one operation, not two phases. Compose in small passes, with the corpus open beside the active scene.

For each scene or meaningful paragraph:

1. Read the exact passage being continued, plus the character, place, artifact, and open-thread records it touches.
2. Write a small continuation that uses those records as live constraints and opportunities.
3. Read the new text immediately, including the paragraph before and after it. Check voice, chronology, object placement, cause and effect, and whether a character is being reduced to one trait.
4. Follow every new durable detail back to its source. If it is newly invented, mark it as a fictional event; if it came from a source, preserve provenance; if it is uncertain, keep it uncertain.
5. Revise the scene while the relevant context is still active. Then continue to the next passage.
6. At the end of the writing pass, update only the durable records changed by the scene and read those records back alongside the chapter.

This creates a live loop:

**read → write → reread → compare → revise → continue**

The loop may move between the novel, character records, artifacts, particles, maps, and image atlas as needed. It should not mechanically consult every file for every sentence. Read the smallest relevant set deeply, then widen the search when a new name, object, place, or contradiction appears.

The immediate reread is not merely proofreading. It is how the story discovers what it has just made true. If a new detail creates a consequence, the next passage should be allowed to respond to it. If it conflicts with established material, pause and reconcile it before extending the conflict.

A chapter is complete only after its prose and its resulting continuity state have both been checked. A successful file write is not itself proof that the story learned.

- Joseph's recording practice includes comparison, selection, and restraint.
- The latch sound remains an open thread for a later arrangement.

Read-back check: the new chapter was compared with Chapter Twenty-Five and Andrew's character record. It uses the established eccentric testing method and the documented growth direction from momentum as reflex toward momentum as shared choice. The scene adds a specific instance; it does not rewrite the character record as a universal trait.
