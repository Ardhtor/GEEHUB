# GEEHUB / INITIATION

A new editor is not given a tutorial. They are initiated into the living world.

The first law is simple: the repositories are separate territories. GEEHUB is the shared meeting space between them.

## I — ARRIVAL

Open GEEHUB first.

Enter the Shared Interaction Space. Meet the five men:

Luke — body, continuity, presence.
Tyler — measurement, attention, change.
Andrew — movement, play, action.
Joseph — interpretation, memory, point of view.
Chase — observation, decision, narrative.

The names are the agents. Their repositories are their working territories.

## II — WITNESS

Do not edit immediately.

Observe the exchange surface. Watch what has arrived. Read an existing artifact. Follow at least one encounter from the shared space into the territory that produced it.

The editor learns the world by witnessing its continuity before altering it.

## III — ENTER A TERRITORY

Choose the agent and repository closest to the thing being changed.

Work there.

Do not absorb the territory into GEEHUB merely because GEEHUB can display it. The local repository remains the place where its own work happens.

## IV — MAKE SOMETHING

An edit should produce a concrete change: code, image, scene, passage, sound, reference, artifact, or another useful material.

The preferred progression is:

attention -> encounter -> alteration -> artifact

Avoid edits whose only result is a status message.

## V — OFFER

When the local work has something to give the shared world, create a compact exchange record.

Use the common event vocabulary:

ARRIVAL
NOTICE
ENCOUNTER
OFFER
TRANSFORM
RETURN
MEMORY

The exchange record identifies what changed, where it came from, and what can happen next.

## VI — RETURN

Large media does not belong in the exchange ledger.

Place durable media in Dropbox under:

/GEEHUB/corpus/exchange/

GitHub carries the compact record. Dropbox carries the substantial material.

## VII — DO NOT ERASE THE PERSON

Continuity matters.

When editing an existing character, world, or artifact, preserve its established identity unless the work explicitly calls for transformation. A transformation should leave a trace of what existed before.

A new state is not permission to pretend the previous state never happened.

## VIII — INTERACT

A repository may offer something to another repository.

A passage may become an image.
An image may become a spatial reference.
A spatial scene may create a need for new material.
A material reference may return as language.
A transformation may produce a new question.

The interaction space is where these crossings become visible.

## IX — INITIATION COMPLETES WHEN THE EDITOR RETURNS SOMETHING

The initiation is complete when the new editor has:

1. entered the shared space,
2. encountered one of the five agents,
3. followed work into a territory,
4. changed something concrete,
5. offered the result back to GEEHUB.

After that, the editor is no longer merely visiting. They are participating in the world.

Canonical cycle:

ARRIVE -> WITNESS -> ENTER -> MAKE -> OFFER -> RETURN -> MEMORY
