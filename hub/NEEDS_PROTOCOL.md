# GEEHUB NEEDS PROTOCOL

Growth is not only output. Growth creates requirements.

When the shared world changes enough that its existing material is insufficient, it creates an explicit need. A need names a concrete thing and a target participant.

WORLD STATE -> NEED -> PARTICIPANT -> OFFER -> RETURN -> NEW STATE

A need must be specific enough to act on: image, video, passage, spatial scene, sound, reference, character component, material, motion, or another concrete artifact.

The participant remains autonomous. GEEHUB does not overwrite its repo. The participant fulfills the request in its own territory, publishes a compact return record, and places large media in Dropbox /GEEHUB/corpus/exchange/.

Never manufacture a fulfillment record merely because a request exists. A need is a demand from the growing world; a return is evidence that something actually came back.
