The production system must generate the intervening body states and preserve identity, pose, camera, clothing, environment, and temporal continuity.

## Findings from the visual evidence

1. **There are two different evidence classes.** Luke-labeled images establish Luke's identity and high-stage appearance. Other multi-stage sequences and dossiers establish useful transformation grammar, anatomy breakdowns and interface patterns. They must not be silently merged into one character.
2. **The existing Luke material is a set of checkpoints, not a complete movie.** Stage 3 → 4, 5 → 6 and 6 → 7 give useful transitions and target states, but the intermediate frames and exact interpolation are still missing.
3. **Whole-body growth is the governing operation.** The phase infographic explicitly distributes change across joints, limb length, torso depth, chest/ribcage, shoulders, arms/elbows, hands, hips/glutes, legs/knees and feet. Growth should not be reduced to enlarging the biceps or applying a uniform scale.
4. **Identity and proportions must remain linked.** Preserve Luke's face, hair, beard, expression character, hand shape, stance logic and recognizable body landmarks while mass and proportions change. The newer 2026-11-25 full-body Luke upload (grey fitted tank and dark short shorts) is an additional clothing/physique reference supplied in conversation; it is not assigned a Library file ID in this analysis.
5. **Clothing and environment are transformation sensors.** Fabric tension, neckline/armhole changes, hem position, shorts fit, foot placement, equipment scale and available room should respond to body growth instead of remaining visually frozen.
6. **The visual timeline should carry the transformation.** The six-panel sequence is a useful storyboard/reference sheet, but the target runtime should produce a single continuous shot or a frame-addressable sequence with scrubbing, playback and stage selection.
7. **Psychosomatic interpretation remains a separate layer.** The manifesto's language around desire, tension, expectation, identity, embodiment and a new baseline can inform character experience. Keep it distinct from visible evidence and from physiological fact.

## Proposed transformation runtime

### Inputs
- A selected subject's baseline image set (front, side, rear and face when available).
- A chosen target-state reference.
- Subject identity and continuity record.
- Growth curve / stage checkpoints.
- Camera, pose, lighting, clothing and environment locks.

### Per-frame transformation
- Track stable landmarks: face, neck, clavicles, shoulder joints, elbows, wrists, sternum, ribcage, waist, pelvis, hips, knees, ankles, hands and feet.
- Grow muscle groups with independent controls rather than one global multiplier: traps/neck, delts, chest, back/lats, biceps, triceps, forearms, abs/obliques, glutes, quads, hamstrings and calves.
- Reconcile joint spacing, limb length, leverage, stance, balance and contact with the floor as the body changes.
- Update skin folds, vascularity, muscle separation, lighting response and surface detail progressively; do not switch texture style abruptly between stages.
- Deform clothing with the body: fabric stretch, seams, armholes, neckline, waistband, shorts legs and folds should change in step with the underlying anatomy.
- Update environment scale cues and object clearance only when the chosen growth curve requires them.
- Preserve camera and background unless the shot deliberately changes.

### Outputs
- A continuous frame sequence or video.
- Stage keyframes with editable parameters.
- A scrubber that interpolates between checkpoints.
- A side-by-side or overlay comparison against source and target.
- A provenance record linking every input and output to its Library source or generated derivative.
- A reusable growth preset for Luke, separate from presets for other characters.

Do not invent a missing Stage 8 or 9 image; interpolate them as generated states and label them as such.

## Evidence / interpretation / application boundary

- **Observed evidence:** what is visible in each Library image and any literal labels embedded in it.
- **Interpretation:** inferred stage relationships, likely continuity links, and the meaning assigned to motifs.
- **Application:** the runtime, morph controls, UI and new generated frames.
- **Canon:** only user-approved character/world decisions; a generated label or infographic number is not automatically canon or a real-world measurement.

## Executable first-pass profile

The first Luke-specific procedural profile now lives at `engine/video/profiles/luke-library-transformation-profile.json`, paired with `luke-library-transformation-timeline.json`. Its curves are normalized procedural authoring values, not measured body dimensions.

A GitHub Actions validation workflow now compiles the renderer modules, checks the profile/timeline contract, and runs renderer-independent curve tests. These checks can validate code and timing data; they do not establish that Blender renders the desired Luke likeness or that the current blockout is anatomically finished.
