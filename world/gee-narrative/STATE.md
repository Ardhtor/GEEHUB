## RGBA body-layer rasterizer added — 2026-11-14
- `core/pixel-frame-renderer.js` adds `renderGrowthDeformationPixels()`, a CPU rasterizer for one ready `geehub.growth-deformation-frame`. It accepts a row-major RGBA source buffer, the exact frame-numbered deformation plan, and decoded binary body and protected-face masks for that same frame.
- Before sampling, it checks source-buffer dimensions and a 12-million-pixel safety ceiling; verifies both masks are same-frame, same-size, non-empty, binary, and disjoint; checks the source mesh lies inside body foreground; rejects source/destination triangles that touch protected-face pixels, leave the image, collapse, or reverse orientation; and refuses overlapping destination triangles that disagree on source coordinates.
- Destination pixel centres are mapped back through triangle barycentric coordinates. Source samples use bilinear interpolation in premultiplied-alpha space to reduce transparent-edge colour fringes. Shared mesh edges are written once when both adjacent triangles agree on their source correspondence.
- The output is a transparent RGBA body layer plus a coverage mask. The source frame is read-only; face and background pixels are not copied into or changed by this layer. This is actual pixel-buffer deformation, but not a complete output frame: PNG decoding/encoding, background reconstruction, face-layer compositing, batch I/O, and Resolve export remain open. `pixelSemanticsVerified` remains false.
- Ten focused tests cover identity sampling, translated sampling, body/face mask exclusion, foldovers, frame mismatches, malformed RGBA and mask data, out-of-bounds vertices, overlapping masks, source-silhouette holes, shared triangle edges, and premultiplied-alpha interpolation. Node 22.16.0 temporary harness: 10/10 passed; `node --check` passed for the renderer and test file. The full studio `npm test` suite and a GitHub Actions result were not available in this run; no full-suite pass is claimed.
- The root README and Studio README now describe the pixel-layer contract and its limits. No local Mac, Dropbox mirror, Resolve session, or user footage was accessed. No PNG file or complete frame was written.
- Next: add a bounded lossless PNG writer/reader path for RGBA frames, then a file-backed frame worker that consumes the exact registered mesh and validated deformation plan while preserving source files. ## Temporal deformation continuity added — 2026-11-11
- `core/mesh-deformation.js` now evaluates the change in each used vertex's deformation offset (`targetPoint - sourcePoint`) across adjacent source frames. Velocity is normalized by the average tracked body-mesh height and divided by the actual timestamp interval; acceleration compares adjacent interval velocities at their midpoint spacing. The validator therefore does not assume a rounded or fixed FPS.
- Default limits are 1.5 body-heights/second for deformation velocity and 40 body-heights/second-squared for acceleration. Callers can override either positive finite limit through `temporalLimits`. Unknown keys, zero/negative values, non-finite values, non-increasing timestamps, and non-contiguous frame numbers are rejected.
- A velocity or acceleration violation changes the sequence status to `blocked-temporal-instability`, marks every frame plan non-renderable, and adds the temporal violation to each frame's validation errors. This prevents a caller from extracting one otherwise-valid frame from an unstable sequence and sending it to the pixel renderer.
- The audit reports measured interval durations, peak velocity/acceleration, the vertex responsible for each peak, configured limits, and violation records. With only two frames, acceleration is unavailable and reported as null; velocity is still checked.
- Five focused tests were added for gradual growth, abrupt velocity, abrupt start/stop acceleration, irregular timestamps, and invalid time/limit inputs. ## Stable mask-derived mesh added — 2026-11-09
- `engine/growth-video-studio/core/mask-mesh.js` builds a fixed-index 2D grid mesh from at least two decoded body/face mask frames. Vertex IDs are assigned by grid row/column; triangle IDs are stable cell/diagonal identifiers. Each frame supplies source-pixel coordinates for the same vertex IDs, mapped across that frame's body-mask bounds.
- Candidate triangles are retained only when every covered pixel centre is body foreground and protected-face background in every supplied frame. The implementation uses per-row prefix sums for exhaustive scanline coverage checks, rejects body/face overlap and non-binary masks, and reports stable-triangle coverage plus rejection reasons. A second pass builds edge adjacency and counts connected components; `meshReady` requires exactly one connected component as well as the configured minimum triangle count. Fragmented grids report `disconnected` instead of being passed to the renderer. The common triangle list is conservative: changing silhouettes may remove triangles from the shared topology.

The audit returns `maskMesh` and a separate `meshReady` flag. `readyForGeometry` continues to describe successful mask intake; it does not imply that a sufficiently dense, edge-connected mesh was found.
- Mesh evidence records that retained triangles avoid the supplied face mask, while `pixelSemanticsVerified=false` remains explicit. This does not prove that the upstream producer segmented the correct anatomy or identified every face pixel. - Each frame can reference separate body and face PNG masks. The body mask must declare face exclusion and the face mask must declare identity protection. Mask URIs must be safe, unique Dropbox GEEHUB references; declared dimensions and SHA-256 formats are checked.
- core/frame-sequence-worker.js verifies the actual referenced files beneath the configured Dropbox root. It refuses symlinked path components, hashes the actual PNG bytes, and checks the PNG signature and IHDR dimensions against the source sequence. It returns a machine-readable audit and performs no writes.
- tools/inspect-frame-sequence.js exposes the worker as npm run inspect:frames. A sequence is marked ready-for-geometry only when frame evidence is structurally complete and every body/face mask file passes checksum and dimension verification.
- Seven focused tests passed under Node 22.16.0 in a temporary harness: ordered/source-matched sequence acceptance; out-of-order, source, and dimension rejection; landmark-only pending state; identity/confidence/temporal failure; actual PNG checksum/dimension verification; checksum mismatch refusal; and symlink refusal. Syntax checks passed for the new core modules and CLI.
- This worker does not run a segmentation model, decode mask pixels, prove that the body mask truly excludes the face, generate a mesh, deform frames, or render a video. The face-exclusion and identity-protection flags remain producer assertions. Local Dropbox/Resolve runtime has not been exercised.


## Articulated mask-mesh deformation added — 2026-11-10
- `engine/growth-video-studio/core/mesh-deformation.js` transfers the articulated growth mapper onto the stable mask-derived grid. A distance-weighted local affine least-squares field maps each source-pixel vertex from tracked body anchors to its target position.
- `buildGrowthDeformationFrame` requires a ready connected mask mesh, matching landmark frame number and timestamp, a complete baseline/target body state, and a decoded protected-face mask explicitly tagged with that same frame number. It validates the source triangles and topology digest before mapping, then retains the mesh's vertex IDs, triangle IDs, topology digest, and triangle index list.
- A frame is renderable only when source and target triangles are non-degenerate and retain orientation, used vertices remain in frame, and neither source nor destination triangles overlap the protected face mask. Out-of-frame growth returns `requires-reframe`; foldovers and face collisions are blocked.
- `buildGrowthDeformationSequence` builds one plan per source frame using the same topology and rejects any cumulative growth channel that regresses between adjacent frames. It does not yet enforce per-vertex velocity or acceleration limits, so stable IDs and monotonic growth are not a claim of fully smooth temporal motion.
- `renderGrowthDeformationFrame` passes only a ready plan to the existing piecewise-affine Canvas warp. Six focused tests cover baseline identity, articulated surface movement, two-frame topology under source motion, growth regression, renderer handoff, and frame/mask evidence mismatch. The renderer test uses a fake Canvas context and verifies draw calls, not browser pixel output.
- The deformation plan consumes decoded masks and tracked landmarks supplied by the caller. No segmentation model, source video, local Dropbox mirror, Mac, or Resolve session was run. The face pixels are not moved; the guard only prevents the body warp from painting over the supplied protected-face mask. Anatomical mask semantics, temporal jitter thresholds, depth/clothing response, bridge registration of mesh evidence, and actual frame-sequence export remain open.
