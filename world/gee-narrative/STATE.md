## Evidence-bound single-frame compositing added — 2026-11-23
- `core/complete-frame-compositor.js` adds `composeGrowthFramePixels()`, an in-memory assembly pass for one timestamped source frame. It consumes the original RGBA frame, same-frame binary body and protected-face masks, a ready transparent body pixel layer from `pixel-frame-renderer.js`, and a version-one temporal scene plate.
- The compositor independently validates source dimensions/frame/time, body/face mask disjointness, scene-plate frame/timestamp membership, binary coverage/unresolved masks, donor-frame provenance, donor thresholds, scene-plate counts/status, and body-layer coverage. The default working ceiling is two million pixels.
- Scene-plate coverage represents the union of body-hidden pixels across the sequence. The compositor applies a reconstructed plate sample only when the current frame's body mask is foreground; it does not overwrite background that is already visible in the current frame. It then overlays the transformed body using straight-alpha source-over.
- Protected-face pixels are left byte-identical to the original source. A body-layer coverage pixel crossing the protected-face mask is rejected. The compositor does not synthesize pixels or alter caller-owned source, masks, body layer, or scene plate.
- If a current-frame original-body pixel has no reconstructed plate sample and is not fully covered by an opaque transformed-body pixel, the original source pixel remains visible and is marked in the output's unresolved mask. The result is `partial-frame` and not ready for assembly. A frame with no unresolved original-body pixels is `complete-frame` and `readyForAssembly=true`; this is a per-frame coverage result, not anatomical or camera verification.
- Results carry per-pixel background and final-layer classifications, pixel counts, and explicit legends. `readyForExport`, `sourceFrameDerivationVerified`, `cameraRegistrationIndependentlyVerified`, and `pixelSemanticsVerified` remain false. PNG writing, batch orchestration, clothing/depth response, and Resolve export remain open.
- Ten focused tests were added for measured background replacement, visible-background preservation, unresolved regions, protected-face priority, source-over alpha, timestamp mismatch, mask overlap, missing plate evidence, and input preservation. The isolated Node 22.16.0 harness passed 10/10 tests and syntax checks using a local fixture for the temporal scene-plate input. The first package workflow run executed all 180 Node tests: 179 passed and one test fixture failed because it corrupted the body/face masks before building the plate, so the upstream scene-plate validator fired before the compositor's own overlap guard. The fixture now builds the valid plate first, mutates the current-frame mask afterward, and calls the compositor directly. The focused rerun passed 10/10 tests and syntax checks; the second package workflow run is pending.
- No personal footage, local Mac, Dropbox mirror, or Resolve session was accessed. The scene plate still depends on externally asserted fixed-camera registration, and upstream mask anatomy remains unverified.

## Lossless RGB/RGBA PNG boundary added — 2026-11-15
- `core/rgba-png.js` adds `decodeRgbaPng()` and `encodeRgbaPng()` as a bounded, dependency-free PNG byte boundary for the existing pixel renderer. The decoder accepts non-interlaced 8-bit truecolour RGB and RGBA PNGs; RGB pixels are expanded to opaque RGBA. It verifies chunk CRCs and ordering, checks the exact decompressed row length, reconstructs PNG filters 0–4, and enforces a 12-million-pixel and 128 MiB default input ceiling.
- The encoder writes row-major RGBA samples to a non-interlaced 8-bit RGBA PNG using filter 0, CRC-protected IHDR/IDAT/IEND chunks, and lossless DEFLATE. It returns a new Buffer; it does not write files or alter caller-owned pixel data. Output bytes are capped at 128 MiB by default.
- Palette-indexed, grayscale, 16-bit, interlaced, and tRNS transparency inputs are refused rather than silently converted. Ancillary color-profile/gamma metadata is not interpreted or copied, so channel samples round-trip losslessly but color-management metadata does not; a production compositor must establish an explicit color-space policy.
- Seven focused tests pass under Node 22.16.0: all five row filters, RGB-to-opaque-RGBA expansion, transparent RGBA round-trip, unsupported encodings, corrupt/truncated/trailing data, pixel/byte ceilings, and malformed output buffers. `node --check` passed for both module and test file. These ran in an isolated temporary harness, not the full Studio suite.

## Temporal deformation continuity added — 2026-11-11
- `core/mesh-deformation.js` now evaluates the change in each used vertex's deformation offset (`targetPoint - sourcePoint`) across adjacent source frames. Velocity is normalized by the average tracked body-mesh height and divided by the actual timestamp interval; acceleration compares adjacent interval velocities at their midpoint spacing. The validator therefore does not assume a rounded or fixed FPS.
- Default limits are 1.5 body-heights/second for deformation velocity and 40 body-heights/second-squared for acceleration. Callers can override either positive finite limit through `temporalLimits`. Unknown keys, zero/negative values, non-finite values, non-increasing timestamps, and non-contiguous frame numbers are rejected.
- A velocity or acceleration violation changes the sequence status to `blocked-temporal-instability`, marks every frame plan non-renderable, and adds the temporal violation to each frame's validation errors. This prevents a caller from extracting one otherwise-valid frame from an unstable sequence and sending it to the pixel renderer.
- The audit reports measured interval durations, peak velocity/acceleration, the vertex responsible for each peak, configured limits, and violation records. With only two frames, acceleration is unavailable and reported as null; velocity is still checked.
